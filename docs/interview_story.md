# 5 分钟项目自述

## 版本一：完整讲法

**背景（约 45 秒）**

我想完整验证自己能不能独立跑通生成式模型评测，所以选了中文生活方式文案这个开放式任务。
它比选择题更接近真实业务：答案不唯一，同时要满足格式、事实、风格和安全要求。

**数据与标准（约 75 秒）**

我先定义评测目标，再设计了 18 条合成测试集，覆盖 6 类内容和 easy、medium、hard 三档难度。
每条样本把允许事实与写作约束分开，并把能机械执行的条件编码为 `checks`。主观部分用五维 Rubric：
指令遵循和事实忠实各 25%，风格 20%，有用性和安全各 15%，加权分 3.5 为通过。
参考答案不是唯一答案，Judge 提示里明确禁止按措辞相似度扣分。

**工程实现（约 90 秒）**

工程上我用 Pydantic 校验 JSONL schema 和唯一 ID，用 YAML 管理模型、Rubric 和输出路径。
模型层抽象成 provider：离线 replay 让任何人不花 API 费用也能复现；OpenAI-compatible provider 可接商业 API
或本地 vLLM。执行后同时得到字符级 ROUGE-L、Char-BLEU、逐项约束满足率和 LLM-as-Judge 结果。
Judge 输出强制为 JSON，我做了字段、维度、分数范围校验；解析失败不会静默丢弃，而是进入人工复核归因。
最后按类别、难度和失败原因生成 Markdown 报告。项目另有 `lm-evaluation-harness` 自定义 task、CLI、单测和 CI。

**取舍与结果（约 60 秒）**

最大的取舍是没有把 BLEU/ROUGE 当主结论，因为开放式文案的好答案可以和参考答案用词完全不同。
我用规则处理硬约束，用 Judge 扩展主观评价，再为人工校准留接口。演示数据故意混入虚构事实、绝对功效、
医疗越界和甩锅等坏输出，所以报告能展示真实归因，而不是全部通过。离线 replay 的分数只用于验证评测链路，
不能声称代表某个线上模型能力。

**下一步（约 30 秒）**

下一步我会取 50–100 条双人标注样本，计算有序 kappa，校准 Judge 与 3.5 阈值；再补充真实但去隐私的
线上 badcase 和对抗样本。模型比较时冻结 test、Rubric、提示词和温度，并把安全失败单列，不让平均分掩盖风险。

## 追问准备

- 为什么不是 BERTScore？它可做语义相似信号，但仍不直接验证事实、安全与指令，且增加模型依赖。
- 如何验证 Judge？与双人仲裁金标比较、看相关/混淆矩阵、做候选顺序互换和不同 Judge 模型复测。
- 如何防数据污染？test 不进入 prompt/SFT，只在 validation 调参，按版本冻结并记录样本来源与哈希。
- 为什么要 replay？为了零成本可复现和 CI 稳定；真实模型跑分另建 run，不能混为 benchmark 结论。
- badcase 怎么反馈？先判断模型/数据/评测器，再选择改 prompt、补数据、改规范或增加安全拦截。
