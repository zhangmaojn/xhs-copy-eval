# 一页评测方法论

## 主流程

**目标定义 → 测试集设计 → 方式选型 → 指标与阈值 → 执行 → badcase 归因 → 反馈迭代**

1. 先把“好”翻译成可决策的能力：本项目要判断文案是否满足约束、忠于事实、自然有用且安全。
2. 建测试集时看覆盖度、难度区分度、抗污染、可验证性和标注一致性（IAA）。
3. 根据问题选工具：硬约束用规则，参考相似度用文本指标，开放式质量用人工/LLM Rubric。
4. 阈值必须在看测试结果前定义；本项目五维加权总分达到 3.5 才通过。
5. 报总分之外必须切类别、难度和风险标签，平均数不能掩盖关键失败。
6. 每个 badcase 要区分模型问题、数据问题和评测器问题，再决定改 prompt、数据还是模型。

## 三种评测方式的取舍

| 方式 | 适合 | 优点 | 主要偏差/局限 |
|---|---|---|---|
| 自动指标 | 格式、关键词、分类、确定答案 | 快、便宜、稳定 | 与真实质量可能错位 |
| 人工评测 | 高风险、最终验收、偏好判断 | 贴近真实标准 | 贵、慢、有标注员差异 |
| LLM-as-Judge | 大规模开放式初筛 | 扩展快、可给理由 | 位置/长度/风格/自我偏好 |

实践上使用“规则兜底 + Judge 扩展 + 人工校准”。Judge 不能替代 ground truth，只是带偏差的测量工具。

## 指标体系

- 确定性：必含项、禁用项、长度、标签数。
- 表面文本：字符级 ROUGE-L、Char-BLEU；只做诊断信号。
- Rubric：指令遵循 25%、事实忠实 25%、风格 20%、有用性 15%、安全 15%。
- 可靠性：人工双标的加权 Cohen's kappa / Krippendorff's alpha；Judge 与人工的相关和混淆矩阵。
- 业务切片：类别、难度、风险类型、模型版本；高风险项单列而非被平均。

## Judge 校准最小方案

1. 抽取至少 50–100 条，2 名标注员独立打分并仲裁。
2. 冻结 Rubric、锚点和提示词，用同一批样本运行 Judge。
3. 检查维度相关、通过/失败混淆矩阵，以及位置互换后的稳定性。
4. 对 3.2–3.8 的边界分和安全维度低分强制人工复核。
5. 更换 Judge 模型或提示词时重新校准，不能直接串联历史趋势。

## Badcase 归因树

```text
失败
├─ 模型问题
│  ├─ 指令遵循
│  ├─ 事实性 / 幻觉
│  ├─ 风格错配
│  ├─ 信息价值不足
│  └─ 安全与合规
├─ 数据问题
│  ├─ 任务歧义
│  ├─ 事实不足 / 冲突
│  └─ 标签或参考错误
└─ 评测问题
   ├─ 指标错位
   ├─ Judge 偏差 / 解析失败
   └─ 阈值与业务风险不匹配
```

## 面试表达模板

每个决策用 **背景 → 方案 → 取舍 → 结果/下一步** 表达。例如：

> 开放式文案没有唯一答案，所以我没有把 BLEU 当主指标；我把可验证条件编码成确定性检查，
> 再用五维 Rubric 做 Judge，并保留人工校准入口。这样兼顾规模与可解释性，但 Judge 仍有偏差，
> 因此边界分和安全失败必须人工复核。
