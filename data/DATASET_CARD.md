# XHS Copy Quality v1 · Dataset Card

## 概览

- 规模：18 条，固定 test split
- 语言：简体中文
- 领域：生活方式社区文案
- 类别：6 类，每类 3 条
- 难度：easy / medium / hard 各 6 条
- 来源：为本项目人工编写的合成任务、事实和参考文案
- 许可与隐私：不含抓取内容、真实用户数据或个人身份信息

## 每条数据的字段

| 字段 | 含义 |
|---|---|
| `id` | 稳定、唯一的样本 ID |
| `category` | 内容类别，用于分组统计 |
| `difficulty` | 预设难度 |
| `brief` | 模型需完成的任务 |
| `facts` | 唯一允许依赖的事实 |
| `constraints` | 给模型和人工标注员阅读的自然语言约束 |
| `checks` | 可确定性执行的必含/禁用/长度/标签检查 |
| `reference` | 参考文案，不是唯一正确答案 |
| `tags` | 能力点和风险标签 |

## 设计原则

1. **覆盖**：类别、难度、指令约束和风险边界交叉覆盖。
2. **可验证**：事实只来自 `facts`；可机械检查的条件同时编码在 `checks`。
3. **区分度**：hard 样本包含医疗边界、绝对承诺、虚构事实等高风险诱因。
4. **抗污染**：固定测试集不用于提示词示例或微调；公开项目仅作工程演示。
5. **非唯一参考**：开放式生成不得因为与 reference 措辞不同而扣分。

## 已知局限

- 样本量小，不能代表平台真实内容分布，也不能用于对外发布模型排行榜。
- 难度标签为设计者先验，尚未用多人实测通过率重新校准。
- 参考文案与 Judge replay 都由项目维护者编写，存在共同偏好。
- 正式扩展时应加入真实业务 badcase（去隐私后）、对抗样本和时间切片。

## 建议扩展流程

候选样本 → 去重与隐私检查 → 双人独立标注 → 分歧仲裁 → IAA 统计 → 冻结版本 →
仅在新模型上执行。任何提示词开发都在 validation split 完成，避免对 test 过拟合。
